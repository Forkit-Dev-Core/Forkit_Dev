EXISTING MANUAL REPORTING

A small receipt.
A record that adds up.

This preserved schema-v1 metrics preview shows manual contributions only. New usage-v2 reporting uses separate consent and totals on the hosted Session Receipt candidate. Local receipts work fully without reporting.

Not connected to a collector. No activity numbers are available.

Private installs and offline activity cannot be counted by the website. No example number is a traction claim.

What these numbers mean
Reporting profiles
Random opt-in profiles with a current report received within seven days. One profile belongs to one selected local store. Reinstalls or separate stores can create another profile; this is not a count of unique people or all installs.
Successful scans
Selected Radar CLI scans whose requested sources all completed or were absent. Failed or partial attempts are counted separately. Only scans recorded while reporting was enabled are included.
Weekly Active Passports
Distinct consistent selected Agent Passport references in receipts this UTC calendar week, counted once within each profile. The same Passport can appear in several profiles. This does not count authenticated agents or model execution.
Repeat-check rate
Profiles with a receipt or scan on at least two different UTC days this week, divided by profiles with either activity on at least one day. No eligible profiles means no percentage.
Receipts, changes and Passport versions
Current UTC calendar week plus three previous weeks, from the latest report per current profile. Receipts can predate reporting consent and are included only through an explicit preview. Passport versions count distinct Core IDs actually created through the Radar CLI while enabled; other creation paths are outside measurement.
Reconstructable-change rate
Recorded meaningful changes with a checked local Passport + session + before/after revision trace, divided by all recorded meaningful changes, including gaps between sessions. Unknown edits cannot enter this denominator. If original counts cannot be established, the percentage is unavailable. Traces are unsigned local evidence, not authenticated AI authorship.
Model and agent observations
Sum of each reporting profile's latest recorded scan observations from the last seven UTC dates. They describe configured metadata, can overlap across sources/profiles, and do not establish runtime use or globally unique systems.
Privacy, consent and withdrawal
The separate metrics feature is off by default and sends only an explicitly approved preview. A separate random profile and revocable credential control each contribution. Public metrics require at least five current profiles. This reduces direct exposure of a single report but does not provide anonymity. The collector receives connection metadata; no prompts, code, chats, secrets, project/file/model names or Passport IDs enter the contribution.

Only the latest contribution from each profile counts. Identical retries do not increase totals. Withdrawal removes the contribution; stale profiles leave current totals after seven days. Already copied public counts cannot be retracted.

Contribute only when you choose

After your first useful local result, use the collector address supplied by its operator:

forkit-radar metrics enable --endpoint <collector-base-ending-/api/v1/radar>
forkit-radar metrics preview --output contribution-preview.json
# Read the exact preview, then send that file and its printed SHA-256:
forkit-radar metrics send --preview contribution-preview.json --sha256 <printed-hash>
forkit-radar metrics disable
# Disabling stops local reporting. To remove an existing public contribution:
forkit-radar metrics withdraw

No collector is preselected. Sending these counts does not publish a verified Passport, create an account, or enable cloud sync.

Useful without giving Forkit your work.

Install, capture, create a local Passport, browse history and generate a share card. Every local step works without a Forkit account.

Private receipt. Local storage.

Forkit compares bounded, supported project files and declared metadata. Source bytes are processed transiently; source contents, prompts, chats and command arguments are never stored or uploaded. Private JSON can contain project-relative filenames and declaration details.

A share card with fewer details.

Only fixed labels, rounded duration, counts and comparison states. No project or agent names, paths, Passport IDs, dependency names, secrets or chats. Generate it locally, review it, then choose whether to share. No publishing happens automatically.

A short guide for your first trial

Open the supplied beta kit's start page, check prerequisites, and choose the editor or CLI workflow. The guide also offers an isolated example and optional count reporting.

Open the beta guide →

~/.local/bin/forkit-radar doctor
~/.local/bin/forkit-radar start --tool cursor
# Work in your editor, then return to the same Git project:
~/.local/bin/forkit-radar stop

For a CLI agent, use session run --tool codex -- codex or session run --tool claude-code -- claude. Your AI tool's own login requirements are independent of Forkit.

Offline kit: extract the matching platform/Python bundle, then run sh install.sh. Its Python and Git prerequisites are explicit. The source installer downloads pinned Python dependencies; neither installer fetches a public Forkit package.

Private beta candidate: Apple silicon macOS/Python 3.11 and Ubuntu ARM64/Python 3.12 kits. No Windows/native desktop app or universal installer claim. Outside-user validation is pending; examples and test results are not traction.

Verified public Passport publishing, cloud sync, cross-device history and team/company or GitHub organization features may require authentication when available. They are outside this local beta. Optional aggregate reporting uses a separate reporting credential and never requires a Forkit account. Your first useful result stays local.
